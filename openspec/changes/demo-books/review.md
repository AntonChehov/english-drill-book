### F1 A worker file that does not arrive is reported as a damaged book, and trying again never recovers

- Where: src/ui/demo/add-demo.ts:56, src/ui/demo/add-demo.ts:60, src/storage/pdf/text.ts:12
- Problem: when the request for the pdf.js worker (`assets/pdf.worker.min-*.mjs`, 379 kB gzip, the largest file of the feature) fails, pdf.js falls back to a "fake worker", whose `import()` of the same file fails too, and rejects with `Error('Setting up fake worker failed: …')`. That is not a `TypeError`, so `add-demo.ts:61` reports it as `unreadable`: the visitor reads «Демо-книгу «Everyday Grammar: A Demo Course» не удалось прочитать: файл повреждён или не той версии», which is false, since nothing was wrong with the book. Worse, pdf.js keeps the rejected set-up of the fake worker for the life of the page (`PDFWorker._setupFakeWorkerGlobal` is memoised with `shadow(...)`), so "Попробовать ещё раз" fails the same way after the network is back, until the page is reloaded. That breaks the delta-spec scenario "Trying again" (the network is back, the visitor tries again, the demo is added without reloading). Reproduced on the production build with Playwright on Chromium and Firefox: abort the request matching `/pdf\.worker.*\.mjs$/` once, press "Попробовать демо" (message above), remove the route, press "Попробовать ещё раз": the same message again, every time. The same probe on the `add-demo-*.js` chunk and the `pdf-*.js` chunk gives the network message, and the retry adds the demo, so only the worker is affected. A dropped connection while this file downloads is likely on a phone, and C-13 lists phones for the demo. What should happen: a worker that cannot be loaded is reported as a network failure («нет связи с сайтом»), and a retry once the network is back adds the demo without a reload. For example, `loadPdfText` could create the worker itself for each attempt (a module `Worker` on the worker URL handed to `getDocument` as `worker: new PDFWorker({ port })`, its `error` event turned into a network failure) instead of leaving pdf.js to fall back and remember the failure. Add an end-to-end test like the "Trying again" one that fails the worker instead of the drill book.
